# Implementation Plan: AI-Powered Todo Chatbot

**Branch**: `004-ai-chatbot` | **Date**: 2026-01-29 | **Spec**: [spec.md](./spec.md)

## Summary

Build an AI-powered chatbot interface that enables users to manage their todo tasks through natural language conversation. The system uses MCP (Model Context Protocol) architecture with OpenAI Agents SDK for intent recognition and tool-based task operations. The chatbot maintains conversation history in a stateless server architecture, persisting all state to PostgreSQL database for scalability and resilience.

**Core Value**: Users can create, view, complete, update, and delete tasks by simply conversing with the chatbot in natural language, without navigating traditional UI forms or interfaces.

## Technical Context

**Language/Version**: Python 3.13+
**Primary Dependencies**: FastAPI, OpenAI Agents SDK, Official MCP SDK, SQLModel, OpenAI ChatKit (frontend)
**Storage**: Neon PostgreSQL (existing database + new conversation/message tables)
**Testing**: pytest (backend), Jest/React Testing Library (frontend)
**Target Platform**: Web application (backend: Linux server, frontend: browser)
**Project Type**: Web (separate backend and frontend)
**Performance Goals**: <3s response time (p95), 100 concurrent users, 10k messages/day
**Constraints**: Stateless server (no in-memory state), existing task schema unchanged, <500ms DB queries
**Scale/Scope**: 6 user stories, 5 MCP tools, 2 new database tables, 1 chat endpoint, OpenAI ChatKit UI

## Phase 1: Design & Contracts

### Data Model Design

**New Entities** (to be detailed in `data-model.md`):

1. **Conversation**
   - Fields: id, user_id, created_at, updated_at
   - Relationships: One-to-Many with Message
   - Indexes: user_id for fast user lookup

2. **Message**
   - Fields: id, conversation_id, user_id, role (user/assistant), content, created_at
   - Relationships: Many-to-One with Conversation
   - Indexes: conversation_id for history retrieval

**Existing Entities** (reused from Phase II/III):
- Task (from Phase II)
- User (from Phase III)

### API Contracts

**Chat Endpoint** (to be detailed in `contracts/chat-api.yaml`):
```
POST /api/{user_id}/chat
Request: { conversation_id?: int, message: string }
Response: { conversation_id: int, response: string, tool_calls: array }
```

**MCP Tools** (to be detailed in `contracts/mcp-tools.json`):
1. add_task(user_id, title, description?)
2. list_tasks(user_id, status?)
3. complete_task(user_id, task_id)
4. delete_task(user_id, task_id)
5. update_task(user_id, task_id, title?, description?)

### Integration Points

1. **Existing Task Database**: Read/write to existing `task` table
2. **Existing Authentication**: Validate user_id from existing auth system
3. **New Conversation Storage**: New `conversation` and `message` tables
